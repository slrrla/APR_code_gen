The root cause is that `circuit.append()` receives an opflow `PauliSumOp` instead of a gate. Qiskit wraps that operator as a sub-circuit instruction (`"circuit-304"`), and `to_gate()` rejects it because it is not a gate.

The operator itself is fine: `0.5*I - 1j*sqrt(0.75)*Y` equals `exp(-iθY)`, which is unitary. So the fix is to build it as a `quantum_info.Operator` and add it with `circuit.unitary(...)`. That gives a `UnitaryGate`, which `to_gate()` accepts.

I also replaced the `qiskit.opflow` import. Opflow is deprecated and removed in Qiskit 1.0, and building the matrix as an `Operator` avoids it.

```python
import numpy as np
from qiskit import QuantumCircuit
# FIX: opflow operators (removed in Qiskit 1.0) were used -> import quantum_info Operator, because it can be turned into a proper UnitaryGate
from qiskit.quantum_info import Operator

circuit = QuantumCircuit(1, name='R')
# FIX: appending a PauliSumOp created a non-gate "circuit-xxx" instruction -> build the Operator and add it with circuit.unitary, because a UnitaryGate is a Gate and to_gate() accepts it
circuit.unitary(0.5*Operator.from_label('I') - 1j*np.sqrt(1-0.5**2)*Operator.from_label('Y'), [0])
circuit.to_gate()
```

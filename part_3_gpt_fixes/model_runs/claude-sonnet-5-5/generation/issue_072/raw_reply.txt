The layout maps both `qreg[0]` and `qreg[5]` to physical qubit 12. A layout must be one-to-one, so a duplicate physical qubit produces an invalid mapping, and that is what triggers the "not a DAG" error. Changing `qreg[5]` to an unused physical qubit makes the mapping unique.

The layout also uses physical qubits up to 17, while a 7-qubit register is being transpiled. The simulator has no coupling map, so this is not a problem. I picked 5 for `qreg[5]` because it is unused and sits in a sensible range.

```python
import qiskit as qk
from qiskit import Aer
from qiskit.ignis.mitigation.measurement import complete_meas_cal

_backend = Aer.get_backend('qasm_simulator')

qreg = qk.QuantumRegister(7)
# FIX: qreg[0] and qreg[5] both mapped to physical qubit 12 -> map qreg[5] to unused qubit 5, because a layout must be one-to-one and the duplicate made the mapping invalid
layout = {qreg[0]: 12, qreg[1]: 11, qreg[2]: 13, qreg[3]: 17, qreg[4]: 14, qreg[5]: 5, qreg[6]: 6}

meas_calibs, state_labels = complete_meas_cal(
    qubit_list=[0, 1, 2], qr=qreg, circlabel='mcal')
print(meas_calibs[0])
qk.compiler.transpile(meas_calibs, backend=_backend, initial_layout=layout)
```

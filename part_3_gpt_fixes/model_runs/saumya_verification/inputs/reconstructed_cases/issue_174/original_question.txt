Solution explanation:
In OpenQASM 2, statement conditionally executes a single quantum operation based on the integer value stored across the classical register rather than on the individual bits. As per the language specs (arXiv:1707.03429): The statement conditionally executes a quantum operation based on the value of a classical register. This allows measurement outcomes to determine future quantum operations. We choose to have one decision register for simplicity. This register is interpreted as an integer, using the bit at index zero as the low order bit. The quantum operation executes only if the register has the given integer value. Only quantum operations, i.e. builtin gates, gate (and opaque) subroutines, preparation, and measurement, can be prefaced by . This fact is repeated in OpenQASM 3 document also (arXiv:2104.14722): The only control flow supported by OpenQASM2 are statements. These can be used to compare the value of a classical bit-register (interpreted as a little-endian representation of an integer) to an integer, and conditionally execute a single gate. An example of such a statement is which would test whether a classical register c (of length three or more) stores a bit-string $c_{n-1} ... c_3c_2c_1c_0$ equal to $0...0101$, to determine whether to execute . If-statements (and classical register comparisons) of this kind are supported in OpenQASM3, as is more general syntax for statements and other forms of control-flow. Also, see this answer: https://quantumcomputing.stackexchange.com/a/4516/9474 Note that, in OpenQASM 3 you can condition on the value of single classical bit: See the example in page 20 in the language specs. Moreover, the document states that: We also extend the if statement syntax to allow for multiple instructions within the body of the , and to allow for an block to accompany it.

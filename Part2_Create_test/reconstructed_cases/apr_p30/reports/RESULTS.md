# p case 30개 APR 결과

**적용 가능. 선택한 버전에서 generated fix 30/30이 변경하지 않은 기존 의도 검증 테스트를 통과했습니다.**

Codex로 조정한 APR 흐름을 실행했습니다. MCP는 비활성이고, 원본 mini-swe-agent/Anthropic 실행 결과는 아닙니다. 각 case마다 검증 이력이 있는 최신 버전 하나를 사용했습니다.

buggy 30/30 실패 · fix 30/30 통과 · generated fix 30/30 통과 · generated fix의 unittest 35개 실행 · 어댑터 계약 테스트 8/8 통과.

첫 전체 검증은 26/30이었습니다. 이후 061/096/1035/189를 검증 피드백으로 수정했습니다. 453은 파일럿 검증에서 helper API 및 반환 규약을 보완했습니다. 최초 결과와 피드백 사용 이력을 보존했으므로 이 수치를 one-shot blind benchmark로 해석하면 안 됩니다.

26개에는 파일럿 피드백 후 통과한 453이 포함됩니다. 저장된 파일럿·전체 검증 기록을 합치면, 후보 테스트의 실패 피드백 없이 통과한 것으로 확인되는 case는 **25개**입니다. 이는 동일 시점에 실행한 별도 pristine 30-case 실험의 점수가 아니라 기록을 교차 확인한 수치입니다. 스크립트 실행 오류를 보며 수정하는 반복과 입력에 제공된 의도 요약은 이 25개에도 허용되었습니다.

**표의 이름:** buggy = 기존 `buggy.py` / fix = 기존 `fixed.py` / generated fix = Codex가 생성한 `patched.py`.

**버전 범위:** case마다 가장 최신 검증 통과 버전 하나만 실행했습니다. 0.25.3은 6개, 0.46.3은 12개, 2.5.0은 12개입니다. 전체 버전 조합을 실행한 결과는 아닙니다.

**Data leakage 구분:** 수리 담당에게 `fixed.py`나 정답 해설을 제공하지 않았고, 사전 조사에서 정답에 노출된 에이전트는 제외했습니다. 다만 기존 검증 메타데이터의 의도 요약을 입력으로 사용했고, 061/096/1035/189/453에는 테스트 실패 피드백을 사용했습니다. 따라서 평가 테스트는 엄격한 held-out 테스트가 아니며, test 정보 노출이 0인 실험이라고 주장하지 않습니다.

**Validation:** 기존에 우리가 만든 case별 `test.py`를 변경하지 않고 사용했습니다. `validator/test.py`는 그 파일의 바이트 단위 복사본이며 SHA256 일치를 확인합니다. 동일 테스트에 `MUT`로 buggy / fix / generated fix를 각각 연결합니다. 원본 ZIP의 단순 종료 코드·stdout 비교 대신 이 테스트 통과를 주요 판정으로 사용합니다.

**Feedback loop 구현 범위:** `adapter.py validate`는 검증을 실행하고 결과를 기록합니다. 자동으로 수리 agent를 다시 호출하는 기능은 없습니다. 이번에는 주 agent가 candidate 실패 진단을 수리 agent에게 메시지로 전달하고, 수정 후 검증 명령을 다시 실행하는 방식으로 반복을 연결했습니다.

**범위 주의:** 009는 SABRE로 GHZ 컴파일을 검증했습니다. 원 질문의 CSPLayout 사용 요구는 남아 있습니다. 018_se는 네이티브 Aer 충돌 기록 때문에 제외했습니다.

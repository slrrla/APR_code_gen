## Pipeline and comparison conditions

- Models: exactly `gpt-6-astra`, `gpt-6-luna`, and `gpt-6-sol`; API availability and response identities were verified. No replacement model was used.
- Inputs: the exact preserved Claude case/version/title/sanitized-question files and fresh original buggy bytes. Reference fixes, evaluation tests, previous repairs, and validation-derived intent summaries were excluded from repair prompts.
- Versions: one pinned version per case, unchanged from Claude: Qiskit 0.25.3 for 6 cases, 0.46.3 for 12, and 2.5.0 for 12.
- Agent: the same `DefaultAgent` source, system/instance prompts, question appendix, observation/error templates, submission sentinel, and monitored Bash environment. Model transport is native OpenAI Responses with one Bash function action per turn, `parallel_tool_calls=false`, `store=false`, and encrypted reasoning replay.
- Limits: 40 API attempts, $1 per case checked before the next request, 1,200 seconds per agent, 120 seconds per shell command, and 8,192 maximum output tokens. The last billed response may exceed the cost limit.
- No reasoning or temperature override was requested. The native responses reported `medium` reasoning effort for all three models. Provider defaults and token accounting can differ from Anthropic.
- Feedback: only script output/errors and harness/format feedback inside the repair loop. All 90 loops closed before final tests started. The generation barrier and candidate hashes verify that the evaluator used the saved generated bytes.
- MCP was disabled. No external documentation tool was available to the repair models.
- Local pinned interpreters and unchanged command guards were used instead of Docker. Git Bash required normal Windows-user process permissions through Codex sandbox escalation. The guards are heuristic and are not OS filesystem/network isolation.

The earlier GPT 6.1 Sol/Codex result used a different orchestration process and final-test feedback, so it is not a model-only comparison with these runs. Prompt exclusions and visible-command audits do not prove absence of memorized training-data leakage or dynamically hidden access.

## Usage costs and excluded infrastructure attempt

An initial `issue_036` cohort failed because Git Bash could not start under the restricted Windows process token (`NtCreateDirectoryObject`, `0xC0000022`). No repair shell command or final evaluation test ran in that cohort. The broker was stopped, all three loops were interrupted, and all requests, responses, trajectories, source snapshots, and hashes were preserved under `records/gpt_p30_environment_failure_01/`.

A no-API check was then added before every paid repair invocation. It executed a fixed print command through the same Bash harness and each pinned interpreter. After all three checks passed under normal Windows-user process permissions, fresh official runs started from the original buggy files. The official `issue_036` results were retained when the remaining cases ran; there was no additional paid pilot after the restart.

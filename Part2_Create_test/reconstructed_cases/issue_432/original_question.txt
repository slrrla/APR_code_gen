Solution explanation:
composes the circuit with its inverse() and this ends up not conforming to the ISA requirement. There is an issue in Qiskit Algorithms specifically about that as well a more general issue around Qiskit Algorithms and ISA circuits. With the code as-is I do not know a solution - if you consider modifying some code then a workaround would be to take a local copy of ComputeUncompute and modify it to transpile the circuit it uses (ie the circuit1 + circuit2.inverse()) for some given backend. It should however still run on local Aer simulator if you use the Sampler from Aer.

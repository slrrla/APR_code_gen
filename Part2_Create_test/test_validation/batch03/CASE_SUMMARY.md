## 468: fixed가 원래 입력을 바꿈

buggy가 다루는 밀도행렬은 X|0>에서 얻은 |1><1|과 Z|0>에서 얻은 |0><0|이다.
두 행렬의 commutator는 0이다.
fixed는 두 행렬을 WeightedPauliOperator로 변환하지 않고, 0.5X와 0.5Z라는 다른 입력으로 교체한다.
이 새 예제의 commutator 계산은 정확하지만 원래 입력 보존 검사는 0.25.0–0.25.3 모두 실패한다.
FIXED_CONTRACT_MISMATCH로 분류했으며, fixed.py는 수정하지 않았다.
테스트는 실제 legacy commutator 호출을 관찰하고 그 결과를 그대로 반환한다. 가짜 계산 결과를 주입하지 않는다.

## 재구성·실행 범위 주의

- 443: 두 코드 모두 변수 이름 control/train_register를 다시 할당하면서 실제 레지스터 이름과 역할이 뒤바뀐다.
  테스트는 제공 코드의 실제 변수 할당과 큐비트 순서를 검증한다. 원본 레지스터 이름 혼동은 RECONSTRUCTION_NOTE로 남겼다.
- 497: fixed는 ListOp를 통한 로컬 일괄 실행과 계산값을 통과한다.
  buggy는 앞선 개별 계산 후 미정의 IBMQJobManager에서 NameError가 난다.
  따라서 원래의 원격 큐/스케줄링 문제 자체를 재현했다고 보지 않고 RECONSTRUCTION_NOTE로 분류했다.
  QasmSimulator.run 관찰자는 실제 백엔드 실행을 그대로 호출한다. 외부 계정이나 원격 작업은 사용하지 않았다.
- 436: 테스트 초안에서 중첩된 Call 안의 Acquire를 직접 보지 못했던 문제를 수정했다.
  최종 검사는 inline_subroutines로 측정 서브루틴을 펼쳐 검사하며, 타깃 소스나 실제 실행은 바꾸지 않는다.
  최종 4개 버전 전부 전체 71개 실험을 실행하여 통과했다.
- 453: 명시적 qubit 목록과 inplace=True 경로에서 할당 및 재사용을 검증했다. 모든 선택적 함수 인자를 보증하는 테스트는 아니다.
- 415: 정확한 회로 상태는 밀도행렬로 전역 위상을 제거해 비교한다. 원본이 출력만 소수점 3자리로 반올림하므로 표시 진폭에는 0.00071 허용 오차를 적용했다.

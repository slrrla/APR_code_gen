# Qiskit APR Ground-Truth Dataset

Reconstructs executable buggy/fixed program pairs from 556 confirmed Qiskit
questions, then validates each pair by running it across 28 historical Qiskit
releases.

Two stages, independently resumable:

| Stage | What it does | Entry point |
|---|---|---|
| 1 | LLM-assisted semantic reconstruction of `buggy.py` / `fixed.py` | `tools/reconstruction/` |
| 2 | Execution matrix across 28 Qiskit versions + classification | `tools/execution/` |

## Credentials

Reconstruction and behavioral-oracle inference call the Anthropic API. The key
is read **only** from the environment and is never written to any file, log,
report, prompt on disk, or generated artifact:

```bash
export ANTHROPIC_API_KEY=sk-ant-...
```

`.gitignore` excludes `.env`, `*.key`, `*.pem`, and credential JSON. If you
pasted a key into a chat or terminal history, rotate it.

## Stage 1 — reconstruction

```bash
python -m tools.reconstruction.run inspect    # profile the workbook
python -m tools.reconstruction.run test       # 78 self-tests, no API needed
python -m tools.reconstruction.run all        # full 556-case run (resumable)
python -m tools.reconstruction.run qa         # dataset-level QA
```

One LLM call per case, reasoning jointly over title, category, question,
buggy code, solution explanation and fixed code. Raw responses are cached
under `.state/llm_cache/` keyed by case + prompt hash, so a resumed run costs
nothing for work already done. Per-case results are checkpointed to
`.state/checkpoint.jsonl`; completed cases are skipped unless `--force`.

Useful flags: `--limit N`, `--workers N`, `--force`, `--no-exec` (static
validation only), `--no-cache`, `--model <id>`, `--provider stub` (offline).

There is also an agent-driven route that needs no API at all, used before the
key was available:

```bash
python -m tools.reconstruction.run agent-next --count 8      # emit a worklist
python -m tools.reconstruction.run agent-ingest --file batch_001.md
python -m tools.reconstruction.run agent-status
python -m tools.reconstruction.run revalidate                # re-derive statuses
```

**Output:** `reconstructed_cases/issue_NNN[_platform]/{buggy.py,fixed.py,original_question.txt}`
plus `reconstructed_cases/reconstruction_report.csv`.

## Stage 2 — version matrix

```bash
python -m tools.execution.run build-envs --pilot   # 6 representative releases
python -m tools.execution.run build-envs --all     # all 28
python -m tools.execution.run envs                 # what actually got built
python -m tools.execution.run oracles --limit 20   # infer behavioral oracles
python -m tools.execution.run test --pilot --limit 15
python -m tools.execution.run test --version 1.2.4
python -m tools.execution.run test --case issue_123
python -m tools.execution.run test --all
python -m tools.execution.run status
python -m tools.execution.run revalidate           # after an environment change
python -m tools.execution.run export               # CSV + Excel only
```

Every `(case, version)` result is appended to
`tools/execution/.state/execution_results.jsonl` the moment it is known, so an
interrupted run resumes exactly where it stopped and never repeats an
execution.

**Output:** `execution_results.csv` (long format, one row per case-version) and
`qiskit_version_validation.xlsx` with sheets `Summary`, `Pair_Matrix`,
`Detailed_Results`, `Environment_Matrix`, `Confirmed_Ground_Truth`,
`Needs_Review`.

## Resuming an interrupted run

Both stages are checkpointed per unit of work, so resuming never repeats
completed work and never needs `--force`.

**Stage 2 (execution matrix) — resume the remaining versions:**

```bash
python -m tools.execution.run test --workers 5 --no-oracle
```

With no `--version` / `--pilot` flag this covers all 28 releases, skips every
`(case, version)` already present in
`tools/execution/.state/execution_results.jsonl`, and executes only what is
left. `--no-oracle` is safe once oracles are cached (all 556 are), and it means
the run makes **no API calls at all** — no key required.

Check what is outstanding first:

```bash
python -m tools.execution.run status
```

Export a completed slice without waiting for the whole matrix:

```bash
python -m tools.execution.run export \
  --version 0.25.0,0.46.3,1.0.0,1.2.4,2.0.0,2.5.0 \
  --prefix execution_results_6_versions \
  --summary-name summary_6_versions.csv
```

After changing an environment (`add-deps`, a rebuild, a Qiskit upgrade),
re-derive execution statuses without redoing reconstruction:

```bash
python -m tools.execution.run add-deps
python -m tools.execution.run revalidate --version 1.2.4
```

`revalidate` re-runs execution and classification only. Reconstruction output
on disk is never regenerated by it.

## Environments

One isolated conda prefix per release under `envs/`, never installed and
uninstalled in place. `envs/spec.json` is the declarative definition;
`envs/manifest.json` records what was *actually* resolved (interpreter build,
Qiskit, Aer, numpy, scipy) so the Environment_Matrix sheet reports fact rather
than intent.

Interpreter choice follows each release's own metadata rather than one global
Python:

| Qiskit | Python | Packaging era |
|---|---|---|
| 0.25.0 - 0.25.3 | 3.9 | metapackage (bundles terra/aer/ignis/aqua/ibmq-provider) |
| 0.45.0 - 0.46.3 | 3.11 | split core; Aer and algorithms installed separately |
| 1.0.0 - 1.2.4 | 3.11 | v1 core |
| 2.0.0 - 2.5.0 | 3.12 | v2 core |

Two rules the historical packaging forces:

* Never add `qiskit-aer` to a metapackage release — it already pins its own Aer.
* Never pin the auxiliary stack. numpy/scipy/Aer are left unbounded so pip
  resolves them *against* the Qiskit pin, which pulls an old release back to a
  contemporary numpy instead of a 2.x that breaks it.

Rebuild one release with
`python -m tools.execution.run build-envs --version 1.2.4 --force`.

## Classification

Per program, per version:

| Status | Meaning |
|---|---|
| `PASS` | exit code 0 |
| `FAIL` | ran in a valid environment and failed |
| `TIMEOUT` | exceeded the wall-clock limit (default 60s) |
| `ENVIRONMENT_ERROR` | **our** setup is missing something (third-party package, interpreter) |
| `VERSION_INCOMPATIBLE` | the case needs a Qiskit API this release does not have |
| `NOT_TESTABLE` | requires IBM Quantum access; never executed |

`ENVIRONMENT_ERROR` and `VERSION_INCOMPATIBLE` are separated by *which module*
the import failure names: a qiskit-family module means a genuine historical
incompatibility, anything else means a gap in our environment. Conflating the
two would invent Qiskit incompatibilities that do not exist.

Pair level: `VALID_REPAIR` (buggy FAIL + fixed PASS), `BUG_NOT_REPRODUCED`,
`FIX_NOT_WORKING`, `REGRESSION`, `NOT_EVALUABLE`.

### Behavioral validation

Exit codes miss logical defects where both programs run cleanly but one prints
the wrong value. For those, a minimal oracle is inferred per case from the
source question and answer — short expected stdout substrings, nothing more —
and cached in `.state/oracles/`. When the source does not pin an expected
output the oracle is `unknown`, and `unknown` is never upgraded by guessing.

`GROUND_TRUTH_CONFIRMED` when **either**:

* **A)** buggy fails as expected and fixed passes, **or**
* **B)** both execute, but the buggy output is demonstrably wrong and the fixed
  output matches the source-supplied solution.

Evidence for (B) is kept in `behavioral_evidence` on every row.

## Source-data facts that shaped the design

Measured from `556_confirmed_qiskit`, not assumed:

* **556 rows**, as expected.
* **`issue_number` is not unique** — 531 distinct values. Stack Exchange and
  Stack Overflow were numbered independently, so 25 numbers appear twice;
  `(platform, issue_number)` is unique. `NAMING_SCHEME = "suffix_collisions"`
  keeps the plain `issue_NNN` form for 506 rows and suffixes only the 25
  collisions (`issue_005_se` / `issue_005_so`). No row is lost.
* **4,425 `---CODE_BLOCK---` separators** across 441 buggy / 427 fixed cells,
  frequently with the same block repeated. Split and de-duplicated.
* **Newlines are destroyed in many cells** — whole programs arrive as one
  physical line. No parser recovers the structure; this is why reconstruction
  is semantic rather than static.
* **3 rows are Excel-truncated** at the 32767-character cell limit
  (issue_ids 40286, 40092, 29447), recorded in `source_truncated_fields`.
* **2 rows have an empty `buggy_code`** cell.
* **`category` is mostly unusable** — 256 empty, and 79% of the rest append a
  verdict essay. Trimmed to the taxonomy label before prompting.

Only `556_confirmed_qiskit` is ever read; `loader.py` refuses the `Summary` and
`562_all_nonvisual_both_code` sheets outright. No URL is followed and no web
source is consulted.

## Safety

Reconstructed programs run in a subprocess that disables sockets before the
target loads, strips IBM credentials from the environment, forces a
non-interactive matplotlib backend, uses a deterministic per-execution working
directory, and is killed at the timeout. Programs whose source references
remote services are never executed and are recorded `NOT_TESTABLE`.

A runtime failure in `buggy.py` is not a reconstruction failure — often it is
the point. A `NameError` is, because it means scaffolding is missing rather
than that the studied defect fired.

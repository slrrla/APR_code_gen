The root cause is that `qiskit.extensions` was removed in Qiskit 1.0, so the import fails. `UnitaryGate` now lives in `qiskit.circuit.library`.

Note that this fix only makes the script run. It will print `unitary`, which is the generic name of `UnitaryGate`. It will not print `x`. Qiskit has no built-in way to turn a matrix into a standard gate name. To get `x`, you would need to compare the matrix against each standard gate, for example with `Operator(XGate()).equiv(Operator(unitary))`. That would be new behaviour rather than a bug fix, so I haven't added it.

```python
import numpy as np
# FIX: qiskit.extensions was removed in Qiskit 1.0 -> import UnitaryGate from qiskit.circuit.library, because that is its current location
from qiskit.circuit.library import UnitaryGate

unitary = np.array([[0, 1], [1, 0]])
gate = UnitaryGate(unitary)
print(gate.name)
```

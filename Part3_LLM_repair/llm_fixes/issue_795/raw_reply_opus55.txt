The root cause is that `QuantumCircuit.append` gets an opflow operator (`PauliSumOp`), not a gate.

- When appended, the operator is turned into a sub-circuit `Instruction`, not a `Gate`.
- `to_gate()` only accepts circuits whose instructions are all gates, so it fails with `"circuit-…" is not a gate instruction`.
- `qiskit.opflow` has also been removed in Qiskit 1.x, so the import alone would fail on current versions.

The fix:

- Build the same operator with `SparsePauliOp`, keeping the `I, X, Y, Z` names.
- Append it as a unitary gate using its matrix.
- The matrix is unitary, because (aI − ibY)(aI + ibY) = (a² + b²)I = I. So it is a valid `UnitaryGate`, and `to_gate()` succeeds.

```python
import numpy as np
from qiskit import QuantumCircuit
# FIX: opflow PauliSumOp (removed API, appended as non-gate Instruction) -> SparsePauliOp from quantum_info, because it builds the same operator and can be turned into a matrix for a UnitaryGate
from qiskit.quantum_info import SparsePauliOp
I, X, Y, Z = (SparsePauliOp(p) for p in 'IXYZ')

circuit = QuantumCircuit(1, name='R')
# FIX: appending the operator object created a non-gate sub-circuit instruction -> append its matrix via circuit.unitary, because a UnitaryGate is a Gate so to_gate() succeeds
circuit.unitary((0.5*I - 1j*np.sqrt(1-0.5**2)*Y).to_matrix(), [0])
circuit.to_gate()
```

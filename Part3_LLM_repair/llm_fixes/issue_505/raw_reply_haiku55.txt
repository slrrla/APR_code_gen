The root cause is that `x` is a `numpy.float64`. In `x * <PrimitiveOp>`, numpy's `__mul__` tries to treat the operator as an array element, which produces the nested object array and the deprecation warning. Putting the operator on the left makes `PrimitiveOp.__mul__` handle the scalar, as it does for the Python float `2.0` in the working case.

```python
from qiskit.opflow.primitive_ops import PrimitiveOp
from qiskit.quantum_info import Pauli
import numpy as np

x = 3.5 * np.sqrt(3.0 / 2)
print(x)

annih_op = PrimitiveOp(Pauli('X')) + 1.0j * PrimitiveOp(Pauli('Y'))
creat_op = PrimitiveOp(Pauli('X')) - 1.0j * PrimitiveOp(Pauli('Y'))

# FIX: `x * op` with x a numpy.float64 dispatched to numpy's __mul__, which built a nested object array -> reversed the order so the PrimitiveOp's __mul__ handles the scalar, because the operator then controls the multiplication instead of numpy
my_op = creat_op.compose(annih_op, front=True) * x

print('type(my_op) = ', type(my_op))
print('my_op)= ', my_op)
```

The layout assigns physical qubit 12 twice, to both `qreg[0]` and `qreg[5]`. That is the root cause.

- `initial_layout` must be a one-to-one mapping from virtual to physical qubits.
- With a duplicate, the transpiler applies the layout and builds a circuit whose operations depend on each other in a loop.
- A circuit with such a loop is not a DAG, so the code raises `DAGCircuitError: 'not a DAG'`.

The fix is to give `qreg[5]` its own unused physical qubit. I chose 15; any qubit not already in the layout works.

```python
import qiskit as qk
from qiskit import Aer
from qiskit.ignis.mitigation.measurement import complete_meas_cal

_backend = Aer.get_backend('qasm_simulator')

qreg = qk.QuantumRegister(7)
# FIX: physical qubit 12 was assigned to both qreg[0] and qreg[5] -> map qreg[5] to unused physical qubit 15, because initial_layout must be one-to-one or the laid-out circuit is not a valid DAG
layout = {qreg[0]: 12, qreg[1]: 11, qreg[2]: 13, qreg[3]: 17, qreg[4]: 14, qreg[5]: 15, qreg[6]: 6}

meas_calibs, state_labels = complete_meas_cal(
    qubit_list=[0, 1, 2], qr=qreg, circlabel='mcal')
print(meas_calibs[0])
qk.compiler.transpile(meas_calibs, backend=_backend, initial_layout=layout)
```
